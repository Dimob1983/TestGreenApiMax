# MAX Chat — тестовое задание (Frontend React)

Веб-приложение для отправки и получения текстовых сообщений в мессенджере **MAX** через [GREEN-API](https://green-api.com/max). Реализовано на React + Vite.

 **Репозиторий:** [github.com/Dimob1983/TestGreenApiMax](https://github.com/Dimob1983/TestGreenApiMax)

##  Возможности

- Вход по учётным данным GREEN-API (`idInstance`, `apiTokenInstance`).
- Создание нового чата по номеру телефона получателя.
- Отправка текстовых сообщений методом [`SendMessage`](https://green-api.com/v3/docs/api/sending/SendMessage/).
- Получение входящих сообщений через [`ReceiveNotification`](https://green-api.com/v3/docs/api/receiving/technology-http-api/) (HTTP API, long polling).
- Автоскролл к новым сообщениям.
- Выход из аккаунта с очисткой сохранённых данных.
- Сохранение учётных данных в `localStorage` — не нужно вводить при каждой перезагрузке.

##  Технологии

- **React 18** — функциональные компоненты, хуки
- **Vite** — сборка и dev-сервер
- **CSS** — стилизация без UI-библиотек
- **Fetch API** — работа с GREEN-API

##  Локальный запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/Dimob1983/TestGreenApiMax.git
cd TestGreenApiMax
```

### 2. Установка зависимостей

```bash
npm install
```

### 3. Подготовка инстанса GREEN-API

Перед запуском приложения нужно создать и авторизовать инстанс в личном кабинете GREEN-API:

1. Зарегистрируйтесь на [green-api.com](https://green-api.com) и войдите в личный кабинет.
2. Создайте инстанс на бесплатном тарифе **Developer**.
3. Авторизуйте инстанс: нажмите **«Получить QR-код»** и отсканируйте его в мобильном приложении **MAX** (раздел «Связанные устройства»).
4. В настройках инстанса:
   - Поле **`webhookUrl`** должно быть **пустым**.
   - Переключатель **«Получать уведомления о входящих сообщениях и файлах»** должен быть **включён**.
5. Скопируйте из личного кабинета значения **`idInstance`** и **`apiTokenInstance`** — они понадобятся при входе в приложение.

### 4. Настройка `apiUrl`

Откройте `src/api/greenApi.js` и замените первую строку на **ваш `apiUrl`** из личного кабинета GREEN-API:

```javascript
// ВАЖНО: apiUrl у каждого инстанса свой. Возьмите его в личном кабинете.
const API_URL = 'https://XXXX.api.green-api.com';
```

> **Почему это важно:** GREEN-API использует разные кластеры для разных инстансов. Если указать неверный `apiUrl`, запросы будут возвращать ошибку 404.

### 5. Запуск dev-сервера

```bash
npm run dev
```

Откройте в браузере адрес, который выведет Vite (обычно `http://localhost:5173`).

### 6. Использование

1. Введите `idInstance` и `apiTokenInstance` на странице входа.
2. Введите номер телефона получателя в формате `79991234567` и нажмите **«Создать чат»**.
3. Напишите сообщение и отправьте его.
4. Ответ получателя появится в чате в течение ~5 секунд (long polling).

##  Известные ограничения

### Лимиты бесплатного тарифа Developer

- Общение возможно только с **3 чатами** в месяц.
- При превышении лимита API возвращает ошибку **466 (correspondentsStatus)**.
- Лимит обнуляется **1-го числа каждого месяца**.
- Для снятия ограничений нужен тариф **Business** (690 руб/мес).

### Особенности MAX

- `chatId` формируется как `79991234567` (номер в международном формате, без `@c.us`).
- Если отправлять сообщения на один номер сначала как `номер@c.us`, а потом как `chatId`, система может считать это **двумя разными чатами** и расходовать квоту дважды.

##  Возможные проблемы

| Проблема | Причина | Решение |
|---|---|---|
| `Ошибка 466` | Исчерпан лимит бесплатного тарифа (3 чата) | Сменить тариф на Business или подождать до 1-го числа |
| `Message cannot be received because custom webhook url is set` | В настройках инстанса указан `webhookUrl` | Очистить `webhookUrl` в личном кабинете и подождать 1 минуту |
| Инстанс в статусе `notAuthorized` | Инстанс не авторизован | Отсканировать QR-код в приложении MAX |
| Сообщения не приходят | `incomingWebhook` выключен, или исчерпан лимит | Включить переключатель, проверить лимиты |
| `Ошибка 401 Unauthorized` | Неверный `apiTokenInstance` | Перепроверить токен в личном кабинете |
| `Ошибка 404` | Неверный `apiUrl` | Взять актуальный `apiUrl` из личного кабинета |

##  Заметки по реализации

- Получение сообщений реализовано через **HTTP API** (long polling), как указано в задании. Webhook не используется.
- После обработки каждого уведомления вызывается `DeleteNotification` — иначе очередь не двигается, и одно и то же сообщение приходит снова.
- Для отправки используется оптимистичное обновление UI: сообщение появляется в чате сразу, не дожидаясь ответа сервера.
- Между итерациями поллинга добавлена пауза 1 секунда, чтобы не превышать лимиты GREEN-API.
- Сообщения из других чатов игнорируются — фильтрация по `chatId`.
